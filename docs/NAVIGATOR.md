# Расписание и справочник политех-навигатора

## Устройство

Источник структуры и предоставленных данных — [campus_assistant](https://github.com/Egorkotik228/campus_assistant). Изучены `src/db_queries.py`, `src/etl_pipeline.py` и дамп `campus_assistant_dump.sql`. Python остаётся полезным для сбора данных, но для трёх запросов не нужен дополнительный HTTP-сервис: наш backend использует существующий `pg`.

Миграция `002_navigator.sql` создаёт схему `navigator` с девятью таблицами, тремя представлениями и записью о последней успешной загрузке. Таблицы `public` приложения не переименовываются и не очищаются. Префиксы `dim`, `fact`, `rel` сохранены для сопоставления с источником: справочники, занятия и связи соответственно.

Флаг `NAVIGATOR_ENABLED=false` оставляет прежний источник расписания. После импорта `true` переключает расписание и корпуса на снимок, включает поиск преподавателей и аудиторий. Документы, дедлайны и отзывы продолжают использовать свои таблицы. При ошибке навигатора не подставляются демонстрационные данные.

## Загрузка

Сначала сделайте обычную резервную копию своей БД перед новой миграцией. Затем в `server`:

```bash
npm ci
npm run db:migrate
npm run data:import-navigator -- --file /полный/путь/campus_assistant_dump.sql
```

На Windows путь с пробелами заключите в двойные кавычки. Не помещайте дамп в публичный Git. На хостинге загрузите его во временную директорию backend и выполните команду там.

Импортёр читает только известные `COPY public.<таблица> (...) FROM stdin` блоки. DDL, psql-команды, смена владельца и параметры pg_dump не выполняются. Колонки проверяются по списку, значения передаются SQL-параметрами. Неизвестная таблица, неполный файл или нарушение внешнего ключа прерывают загрузку.

Повторный импорт без `--replace` завершается ошибкой. Этот флаг разрешает заменить только строки таблиц `navigator`; операция и обновление времени импорта находятся в одной транзакции. Данные основной схемы не удаляются. Параллельные импорты сериализуются транзакционной блокировкой.

После успешной загрузки установите `NAVIGATOR_ENABLED=true` в окружении backend и перезапустите процесс. Это не `VITE_`-переменная. `DATABASE_URL` остаётся прежней. При внешнем TLS-подключении сертификат должен проходить проверку; отключение `rejectUnauthorized` удалено. Если провайдер использует собственный CA, настройте доверенный сертификат по его инструкции.

## Проверка

В pgAdmin, подключённом к БД из `DATABASE_URL`, обновите дерево **Schemas → navigator → Tables / Views**. Проверьте:

```sql
SELECT current_database();
SELECT * FROM navigator.import_state;
SELECT count(*) FROM navigator.fact_lessons;
SELECT group_name, subject_name, weekday_no_or_exam_date, date_from, date_to
FROM navigator.v_full_schedule
WHERE group_name = '261-321'
ORDER BY weekday_no_or_exam_date, pair_number;
```

Для предоставленного 19 октября снимка ожидаются 19 982 занятия, 688 групп, 420 записей аудиторий и 1 114 преподавателей. У другой выгрузки количества могут отличаться. `261-321` — пример и значение по умолчанию в настройках; для своей группы используйте её код.

Затем проверить `/api/health`, главную страницу, `/api/schedule` с известной датой, поиск преподавателя и аудитории в боковой панели. Поддерживаемые вопросы в чате: «Расписание на 2026-10-19», «Какие пары послезавтра?», «Преподаватель Зайцев», «Где находится аудитория Д108?».

Пустой ответ не доказывает отсутствие занятий. Время некоторых занятий и контакты преподавателей могут отсутствовать. HTTP 503 при включённом навигаторе без снимка означает, что загрузка ещё не выполнена. При выключенном флаге поиск преподавателей/аудиторий также отвечает 503.

## Дата и качество данных

Семестровое расписание фильтруется по дню недели и границам `date_from/date_to`. Записи сессии выбираются по точной ISO-дате из поля источника. Подгруппа может быть частью названия предмета: автоматического отбора подгруппы пока нет.

Импортированные сведения помечаются как снимок, а не как проверенные в момент вопроса. Дата «Загружено» показывает время импорта, не время последней проверки университетом. При важных изменениях сверяйтесь с официальным расписанием.

Ограничения исходного ETL: берётся только первый преподаватель из списка; у многих занятий преподаватель не указан; большинство email пустые; непустые исходные таблицы ETL пропускает вместо обновления. Текущая интеграция не исправляет отсутствующие сведения и не выдаёт адрес корпуса за маршрут по этажам.

Следующий отдельный шаг — контролируемое обновление снимка из разрешённого источника с проверкой результата. В текущем изменении нет автоматического скачивания или фонового расписания обновлений.

## Тесты

`npm test` в `server` проверяет SQL во встроенном PostgreSQL через PGlite, а не только через подставные ответы. Есть проверки границ дат, сессии, кириллицы, NULL, экранирования LIKE, запрета произвольного SQL, повторной загрузки и отката после нарушения внешнего ключа. HTTP-тесты проверяют расписание/поиск, неверные параметры и CORS.

Для дополнительной проверки своего полного файла:

```bash
NAVIGATOR_TEST_DUMP_PATH=/полный/путь/campus_assistant_dump.sql npm test
```

Это синтаксис Git Bash/Linux/macOS. В PowerShell задайте `$env:NAVIGATOR_TEST_DUMP_PATH` перед `npm test`. Тест поднимает временную БД в памяти, применяет обе миграции и seed, импортирует файл и проверяет сохранность документов. Он не подключается к рабочей `DATABASE_URL`.

На 19.10.2026 предоставленный полный дамп прошёл эту проверку во встроенном PostgreSQL 18. Проверка не заменяет проверку сетевого подключения, TLS, прав роли и версии PostgreSQL на вашем хостинге. Рабочая БД пользователя из среды разработки не изменялась.
